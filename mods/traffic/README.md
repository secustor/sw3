# sw3-traffic

NPC trader traffic for Star Wolves 3: Civil War (GOG v1.12). The traffic logic is Lua 4.0.1 scripts under `Data/Scripts/Mods/Traffic/`. A `traffic` module in the sw3tp `zlib1.dll` proxy loads them, registers the `TRF_*` natives, calls the Lua entry, load and tick callbacks, and carries the global `TRF` across the global clear on location entry. No game file is edited. Status and the experiment checklist are in [design/PROGRESS.md](design/PROGRESS.md); the build design is in [design/mod-options.md](design/mod-options.md) (sections 5 and 7).

Phase 0 runs experiments E0.1 to E0.3. Phase 1 (v0.1 traffic, [below](#v01-traffic-exp0-traffic1)) and Phase 2 (v0.2, [below](#v02-traffic-exp0-traffic1)) are implemented and host-tested, not yet run in the game.

## Files

`Data/Scripts/Mods/Traffic/` (CRLF, installed to `<game>/Data/Scripts/Mods/Traffic/`):

| file | role |
|---|---|
| `traffic.script` | Loader. The DLL appends it to `sys_IncludeFileList`, so it runs last on every MapInitialization. Defines `TRF_OnEnter/OnActivate/OnLoad/OnTick/BeforeJump`, `TRF_Init`, `TRF_L` (log), `TRF_Dump`. Wraps `TeleportToLocation` and `CustomTeleportate` once, so that `TRF_BeforeJump(dest)` runs before every scripted jump. Loads `config.script`, the experiment file chosen by `exp`, `exp_saves.script` when `autosave` is 1 or 2, and `map.script`. Each callback forwards to `TRF_Exp_<name>` if the experiment file defines it; `OnActivate` also calls `TRF_Saves_OnActivate`. With `exp=0` and `traffic` not 0 it also loads the v0.1 modules below, calls `TRF_InstallGen()` and dispatches each callback to the modules (`design/v01-spec.md` 10.1), each call protected (`TRF_P`). The v0.2 modules load after them, then `TRF_InstallTradeDock` and `TRF_InstallBoard` run; dispatch order in `design/v02-spec.md` 10.3. With `enabled=2` only state, safety and shop load. |
| `config.script` | `TRF_Config()` returns `{exp=0..3, log=0/1, big=0/1, del_on_jump=0/1, autosave=0..2, traffic=0/1}` plus the optional v0.1 keys (`v01-spec.md` 9) and v0.2 keys (`v02-spec.md` 10.4). The repo default is `exp=0, autosave=0, traffic=1`; `install-test.sh` rewrites the file. |
| `trf_state.script`, `trf_safety.script`, `trf_ui.script`, `trf_events.script`, `trf_gen.script` | v0.1 traffic (`design/v01-spec.md` 10.2), extended by v0.2: saved table (v3 since v0.2) and visit state; safety rules, caps, governor and strict gate; player-facing lines and news; attack, heat tiers, kills and response; generator wrap, spawn, routes, queue and seed, manager step, load pass. |
| `trf_region.script`, `trf_tier.script`, `trf_raid.script`, `trf_shop.script`, `trf_hail.script` | v0.2 (`design/v02-spec.md` 10.1): regional cycle, prosperity and clans; bands, tiers, holds, parked ships; raids and help pay; trader shops, shortages and restore; hail menu, contracts and work board. Each loads on its own. |
| `exp_hooks.script` | E0.1: hooks and natives alive. |
| `exp_state.script` | E0.2: `TRF` across jumps and a save. |
| `exp_trader.script` | E0.3: trader life-cycle primitives and the snapshot question. |
| `exp_saves.script` | Baseline save kit (any `exp`): one `AutoSave` per new system, see [Baseline saves](#baseline-saves). |
| `map.script` | Generated by `tools/gen_map.py`: `TRF_MapData()` returns the systems, portals and docking stations (`st`). |

Other files: `env.sh`, `install-test.sh`, `run-test.sh`, `uninstall-test.sh` (test clone), `tools/` (site checker, map generator, Lua lint, Lua 4 build), `tests/` (host harness), `VERSION`.

Script rules: top-level code only defines functions and installs the wrappers. All state lives in the table `TRF`, which holds only numbers, strings and nested tables, and none of its keys is a reserved name. Every global carries the `TRF_` prefix. Object handles are never stored in `TRF`.

## Running the experiments

The game must be launched by the user. The scripts only prepare the test clone (`~/Games/Heroic/sw3-tp-test`) and collect the logs.

    EXP=1 TRAFFIC=0 mods/traffic/install-test.sh   # EXP=0..3; also TRAFFIC, LOG, BIG, DEL_ON_JUMP, AUTOSAVE, OVERRIDE, DUMP, GUARD, the v0.2 keys, PRO_SET, TUNE, TRAFFIC_ENABLED, SITE_T1..SITE_T4, TICK_MS
    SECS=900 mods/traffic/run-test.sh       # SECS defaults to 600; play during that time
    mods/traffic/uninstall-test.sh

`install-test.sh` installs the rebuilt `zlib1.dll` and the scripts, writes `config.script` with the selected experiment, and writes the `[traffic]` section of `sw3tp.ini`. After the game is killed, `run-test.sh` prints the `ExecuteScriptFile` lines from `LOGfile.txt` that load `Mods/Traffic/`, the new `ScriptErrors.log`, and every `traffic:` line from `sw3tp.log`. Lines from the scripts look like `traffic: lua: E0.<n> ...`.

### E0.1 hooks and natives (`EXP=1`)

Start a new game, fly for a while, pause the game for a few seconds, then jump once.

Logs: `top-level load`; `init` lines with `type(TeleportToLocation)` before and after the wrap, `TRF_Version()`, the native clocks and the x87 check `16777216 + 1` and `1/3` (`16777217.0` and `0.33333333333333331` = 53/64-bit precision, `16777216.0` and `0.3333333432674408` = 24-bit); one `OnEnter`/`OnActivate`/`OnLoad`/`BeforeJump` line per event, with counters and the location; one `tick` line per real second with `dt_game`, `dt_real`, their sums over that second, `TRF_GameTime()` and `TRF_RealTime()`.

Pass: `sw3tp.log` shows 7 `attach ok` lines (T1, T2a–T2d, T3, T4) and no `traffic: disabled`. `LOGfile.txt` loads `Mods/Traffic/traffic.script` after the last game include. Each entry gives exactly one `OnEnter` and one `OnActivate`. `sum_game` reads 0 while paused (or the log shows what happens instead). `ScriptErrors.log` has no new lines.

### E0.2 state across jumps and a save (`EXP=2`, optionally `BIG=1`)

Start a new game and jump twice. Save, quit, relaunch and load (the save kit is on by default for `EXP=2` and makes the save itself, see [Baseline saves](#baseline-saves)). Repeat once with a save made with `TRAFFIC_ENABLED=0`. With `BIG=1`, compare the `.sav` size with that of a save made without it.

Logs: each `OnEnter` logs `n`, `PI`, `PI_survived` and a dump of `TRF`. `OnLoad` logs the same values plus `fresh` (1 = `TRF` was nil after the load).

Pass: `n` grows by one per entry, and `PI_survived=yes` after jumps. After the load, `OnLoad` (not `OnEnter`) fires with `fresh=nil`, `n` keeps the saved value and `PI_survived=no`, which shows that the save writer drops the nested reserved key. A save made with the mod disabled loads with `fresh=1`. With `site_t3=0`, `TRF` is recreated on every entry and `n` stays 1.

### E0.3 trader life cycle (`EXP=3`, `DEL_ON_JUMP=0` or `1`)

Enter a system that has a trade station and watch the transport. Attack it once. Wait until it has left and the second transport is docked, then jump out and come back. Run this twice, once with `DEL_ON_JUMP=1` and once with `DEL_ON_JUMP=0`.

What happens: on `OnActivate`, a `Btransport` flight spawns at the portal farthest from the player (if `CreateCarcass` returns nil it tries the next portal) and gets `ComeToTradeStation`. It also gets three string-callback triggers: two arrival triggers (`"TRF_OnArrive(1,1)--"`, `f_object_inside` within 150 of the station; `"TRF_OnArrive(1,2)--"`, `f_inside` within 75 of `GetDockingPosition()`; the first one that fires counts, the log line's `how=` says which), `attack` and `f_died`. After 20 s docked it gets `ComeToPortal` and an `f_object_inside` exit trigger, and on exit the portal plays `Start(5, 0)` and the flight is deleted. Trader 2 then spawns and stays docked. Before the jump, the positions of the live traders are recorded, and with `del_on_jump=1` their flights are deleted. On every `OnActivate`, `GetCarcassCountInSphere` is logged around the recorded spawn point and the recorded last position. Every 5 s the log shows each live trader's position, its distance to the station centre, to `GetDockingPosition()` and to the exit portal. After a load, triggers restored from the save log `stale (no live handle)`.

Pass: `CreateCarcass ... -> ok`, and each callback logs its id (`OnArrive id=1`, `OnAttack id=1`, `OnDied` or `OnExit id=1`). The string callbacks therefore work. The position lines show whether the ship stops at the dock point. On the revisit, the count around the last position answers mod-options question 1: a non-zero count with `deleted=0` means that NPC flights are part of the location snapshot. Every `CHECK` line marks an assumption that the run confirms or refutes.

## v0.1 traffic (`EXP=0 TRAFFIC=1`)

v0.1 ("traders with a purpose", design §12, spec [design/v01-spec.md](design/v01-spec.md)) replaces the vanilla random trader contact in the 79 systems that have one. It is implemented and host-tested; it has not run in the game yet.

### What the player sees

- FTU freighters with a name and a cargo class (`FTU freighter Kestrel`), spawned by the vanilla generator tick at the contact's own portals. They fly portal to portal (path C). Paths A and B (to or from the trade station) use the first `st` entry of `map.script` (75 systems have a trade station).
- At most 2 traffic flights and 10 traffic ships per system (1 flight when the system already holds more than 40 objects), a lifetime of 720 s, and a watchdog that removes stuck traders when out of view.
- A focus line in the screen log the first time a trader is selected or comes within 200 (`FTU freighter Kestrel: machinery, Aurora -> Elio`). The vanilla trade meeting at 70 stays.
- An arrival line 5 s after entering a system with disruption ≥ 3 (`FTU reports raids on the lanes in this system`, three bands).
- Attacking a trader raises heat and starts a response that reproduces the vanilla one. Traders killed by anyone raise the system's disruption, which adds escorts and lowers spawns; pirate kills and time (legs) bring it down.
- Vanilla behaviour is kept, untouched, in: start systems in chapters 1–4 while a story mission is active (`guard`), `elio`, `x297`, `gefest` while a mission is active, systems not in `map.script`, and whenever `__disableAction` is set. During an extortion (`__sys_SOS`) nothing spawns and no line is shown; after 30 s without an extortion flight, nearby traders leave by a portal and distant ones are deleted.

### Config keys

`install-test.sh` writes `exp, log, big, del_on_jump, autosave, traffic` and, when set in the environment, `override`, `dump`, `guard`. Every other key reads as its default (`TRF_OptDef` in `trf_state.script`; full table in spec 9):

| key | default | meaning |
|---|---|---|
| `traffic` / `enabled` | 1 | 0: the v0.1 modules are not loaded (loader, wrappers and kits only). Only loaded with `exp=0`. |
| `log` | 1 | 0 off, 1 info, 2 debug (every decision) |
| `override` | 1 | 1 mod traffic, 0 untouched vanilla, 2 vanilla but counted (M11 baseline) |
| `guard` | 1 | start-system fallback: 1 during missions in chapters 1–4, 2 always in chapters 1–4, 0 off |
| `dump` | 0 | periodic state dump every `dump` game seconds |
| `cap_traders`, `cap_ships`, `spawn_scale` | 2, 10, 1.0 | volume (v0.2: 5, 20, 1.0 over the band row) |
| `ui`, `ui_out`, `ui_focus`, `arrival_line`, `meet` | 1, 1, 3, 1, 1 | text and meeting toggles (v0.2: `meet` 2) |
| `heat`, `dis`, `response`, `dock_mode` | 1, 1, 1, 0 | counters, attack response, docking variant |
| `sys_off`, `sys_deny`, `tune` | `{}` | per-system off switch, extra deny list, tuning overrides |

For other keys, edit `<clone>/Data/Scripts/Mods/Traffic/config.script` after the install (one line, CRLF).

### Running it on the clone

    EXP=0 TRAFFIC=1 AUTOSAVE=1 sh mods/traffic/install-test.sh   # normal v0.1 mode, with the baseline save kit
    EXP=1 TRAFFIC=0 sh mods/traffic/install-test.sh              # E0.1 hook experiment only
    SECS=1800 sh mods/traffic/run-test.sh                         # the user plays; logs land in <clone>/traffic-runs/

Lines in `sw3tp.log` (all `traffic: lua: v0.2 ...` since the v0.2 modules are wired in; v0.1 builds wrote `v0.1`):

- once per location entry: `loaded map=1 modules=10 TeleportToLocation wrapped=1 CustomTeleportate wrapped=1` (5 in v0.1 builds) and `gen: install generator=1 case_eject=1 ... mine=1/1`. `modules` below 5 or a missing install line means the mod stays vanilla: look at the `load <file> failed` line before it.
- `dump enter|load|jump|tick v=3 gen=<n> sys=<name>(<idx>) legs=<n> ... heat=<h>/<n> ... mode=mod|vanilla`, followed by `dump dis <system>=<n> ...` and `dump stat ...`: `gen` grows by one per entry and per load, `legs` by one per entry and every 300 game s in a system; neither goes back. `mode=vanilla` comes with a `safe: mode vanilla why=<reason>` line.
- `gen: spawn id=<n> path=C ...`, `gen: remove id=<n> why=exit|dock|life|stuck|wind|jump|lost|station ...`, `ui say ... text=...`, `st: dis`, `st: heat`, `ev kill`, `ev resp`.
- `dump stat spawn=<n> skip_cap=<n> ...`: spawn, skip and removal counters for this visit.
- `ERROR <message>`: a mod error caught by the mod. It never reaches `ScriptErrors.log`, so any such line is a bug to report.
- `ERROR cb <name>: <message>`: an error in trigger callback `<name>` (spec 13, O1), logged once per callback and visit; repeats only raise `stat err_<name>` and `err` in the dump.
- `ScriptErrors.log` must have no new lines. Mod trigger callbacks run protected (spec 13, O1); a line from `_FTrader_Action` or another vanilla function called by the mod keeps the default handler.

## v0.2 traffic (`EXP=0 TRAFFIC=1`)

v0.2 ("help or prey, and the station consequence", design §12, spec [design/v02-spec.md](design/v02-spec.md)) adds five modules on top of v0.1: `trf_region` (regional cycle, prosperity, clans), `trf_tier` (bands, trader tiers, holds, parked ships), `trf_raid` (lane and staged raids, distress, help pay), `trf_shop` (trader shops, shortages, price restore) and `trf_hail` (hail menu, contracts, patrol work board). It is implemented and host-tested (30 host runs), not yet run in the game. Each v0.2 module loads on its own; a missing or failing file only turns its features off (`loaded ... modules=` below 10).

### What the player sees

- Regions and clans: the 110 connected systems form 8 regions around the pirate homes. Each region cycles through Quiet, Boom, Build-up, Raids, Bust and Recovery once every few dozen legs (a leg is a jump or 300 game s). The phase moves the region's prosperity (`pro` 0–9) and the clan score. Off-screen faction sweeps end the Raids phase. The clan has a name (`Ash Vipers`) that shows in radio lines, answers and news.
- Prosperity bands: systems with high `pro` spawn more traffic (up to 4 flights and 16 ships at `pro` 5–9) and bigger traders (TT1 to TT3, TT3 with escorts and expensive cargo). A parked freighter sits at the trade station while the player is in the system. A new arrival line tells the band (`FTU: trade hub, convoys run here`).
- Docking queue: up to 3 traders wait at hold points near the station and dock one at a time; the player gets priority. A seed trader arrives 15–30 s after entry with a chance that depends on the band.
- Lane raids: a pirate flight intercepts a trader (`Ash Vipers: Cut your engines and drop cargo, trader.`). The trader either complies (`Cargo released. Don't shoot.`) or refuses, flees and calls for help (`FTU Whimbrel: pirates on us, any ship assist!`) with a nav marker. A player who damages or kills the raid ship gets paid by the trader (`Thank you, Wolves. We owe you.`). Staged raids: entering a system with disruption ≥ 3 (≥ 5 in a guarded start system) can start a raid on a trader near the player, with a 180 s window.
- Hail: the trader announces itself at 70 units (`FTU Albatross, open for trade. Best market in the sector.`). Selecting it within 150 units opens a chain of boxes: OK picks the option, Cancel moves to the next. The options are Trade (its own `trf_<class>` shop with the hold's cargo), Where are you headed? (direction plus one rumour), Any news? (the vanilla paid rumour), Need an escort? (contract to its exit or station, pay fixed at accept), Where is traffic in trouble?, and Where is trade booming?. At heat ≥ 3 traders refuse (`We have nothing to say to the Wolves.`).
- Patrol-station work board: docking at a patrol station first shows a `Patrol report` box (raids and booming lanes within 3 jumps). When the report text has not changed since the last docking, a screen-log line replaces the box.
- Shortages: a killed or robbed path A trader, or a region entering Bust, makes its cargo class short at the target station for 6 legs. The station then buys that class at +50 %. When the shortage ends, the vanilla price comes back at the next docking there. At most 8 stations change, and all are listed in `TRF.shops`.
- Heat tiers: heat 3 makes traders flee from the player; heat 5 limits spawns to TT2, and the response grows with the tier. Killing traders in a system lowers its `pro` by 3 per kill (kill cap 3 per visit).
- News: a bulletin line on arrival (`FTU bulletin: Trade booming near Elinor`), one per topic.
- Strict gate: in the 89 quest systems during a mission, the board box, raids, TT3, bands and price writes are off (`safe: gate ... denied why=mission_q`).

### Config keys (v0.2)

Defaults are in each module's `TRF_<M>_OptDef()`; a missing key reads its default. The repo `config.script` lists them all. `install-test.sh` writes only the keys that are set in the environment (names in capitals, e.g. `HAIL_START=2`):

| key | default | meaning |
|---|---|---|
| `enabled` (env `ENABLED`) | 1 | 2: restore-and-stop. Only state, safety and shop load, and every trade docking restores that station's changed prices (see Removal) |

| `cap_traders`, `cap_ships`, `spawn_scale`, `band_half` | 5, 20, 1.0, 0 | limits over the band row (v0.1 defaults were 2, 10); halved band steps |
| `parked`, `seed`, `queue` | 1, 1, 1 | parked ship, arrival seed, docking queue |
| `raids`, `staged`, `contracts`, `esc_speed` | 1, 1, 1, 0 | lane raids, staged raids, escort contracts, contract speed cap (0 off) |
| `meet`, `hail_start`, `board` | 2, 1, 1 | `meet` 2: announce line and hail (1: vanilla meeting box, 0 off); `hail_start` 2: menu opens at the announce without a focus; `board` 2: screen line only, 0 off |

### Log lines (v0.2)

All lines are `traffic: lua: v0.2 ...` in `sw3tp.log`. The v0.1 lines above still apply.

- Load: `loaded map=1 modules=10 ...` (5 v0.1 + 5 v0.2; 3 with `enabled 2`), `gen: install ...`, `shop: install trade_dock=1 mine=1`, `hl: install board=1 mine=1`. A missing install line or `load <file> failed` names the missing feature.
- Dump (on entry, load, jump and every `dump` s): `dump enter v=3 ... help=<n> rt=<n>`, then `dump rg n=8 rt=<leg> QBURXV... sc ...` (one phase letter per region: Q Quiet, B Boom, U Build-up, R Raids, X Bust, V Recovery, then the clan scores), one `dump rg <slot> <home> ph=<phase> len=<n> sc=<n> tier=<n> sn= sl= ...` per region, `dump pro <sys>=<pro> ...`, `dump tier pro= band= sf= caps= ...`, `dump raid ...`, `dump hail ...`, `dump shop short ... shops ...`, `dump gate=ok|<why> sys= strict= ...`.
- Cycle: `rg: init fresh=1 slots=8/8 ...`, `rg: tick x<n> legs=<L> <letters> sc ...` (every 2 legs), `rg: sweep <slot> planned|attempt <k> won|failed ...`, `rg: pro <sys>(<idx>) <old> -> <new> (<why>)`, `rg: clan <slot> <old> -> <new> (<why>)`, `rg: pro_set <sys> = <n>`.
- Entry: `tier: entry <sys> pro= band= sf= caps= parked= gov=`, `gen: entry plan: seed chance= roll= in <s> s`, `gen: seed id= tier=`, `tier: parked <label> at ...`, `gen: queue id= hold= ...`.
- Spawn: `gen: spawn id=... tier=<1..3> hold=<n>`.
- Raids: `raid: go n= id= via= tier= ships=`, `raid: demand`, `raid: comply ... lost= dis=`, `raid: refuse`, `raid: sos id= why=raid|staged|heat nav=`, `raid: flee`, `raid: help counted ...`, `raid: paid n= id= cr=`, `raid: end n= id= how= ...`, `raid: staged planned|spawn|window end ...`.
- Hail and contract: `ui announce id= band=`, `hl: hail id= via=focus menu n=`, `hl: hail id= option <name>`, `hl: contract id= accepted n=<cr>`, `hl: contract id= exit paid n=<cr>`, `hl: board box|line ...`.
- Shops: `shop: open id= trf_<class> s= b= ...`, `shop: short new <sys>(<idx>) cls= till=<leg>`, `shop: short expire ...`, `shop: apply <shop> cls= s= b= ...`, `shop: restore <shop> ...`, `shop: restore done|pending=<n>` (`enabled 2`).
- Other: `st: help <old> -> <new> (<why>)`, `ui news post <topic>=<v> slot= mode=`, `safe: gate <feature> denied why=<reason> sys=`.

## Baseline saves

No `.sav` exists on this machine and agents cannot run the game, so the first play session has to produce the baseline saves. The mod makes them itself with the game's `AutoSave` native when `autosave` is set (`AUTOSAVE=1`, the default for `EXP=2`); the manual recipe below is the fallback.

### What `AutoSave(text)` does (native `0x5e6ff0`)

Tags: [C] read in `.work/exe.asm`, [I] inferred, [U] unknown. Details of the file format are in [design/mod-research/save-format.md](design/mod-research/save-format.md).

- It returns at once unless the profile option `autosaveOn` is set (`Game+0x290 -> +0x14 -> +0x5c`; `0x4e7d45` loads that field from the key `autosaveOn`) [C]. In the clone, `Profiles/secustor/profile.info` has `AUTOSAVEON=1` ("Enable autosaving" in the options) [C file, I that this is the same key].
- It needs one string argument, otherwise it logs `ScriptDispatcherServices::AutoSave(): invalid params!` [C].
- The argument is the display text, not a file name and not necessarily a localisation key. It goes through `LocalizationManager::GetString` (`0x59c870`), which returns any text that is empty or does not start with `#` unchanged [C], and looks up `#` keys case-insensitively (`_strupr`, `0x67bec5`) [C]. The developers' `include/AutoTest2.script` calls `AutoSave('System_'..name)` [C]. Free text therefore works [C code, I in-game].
- Save name = localised `#UI_AutoSave` (`ui_common.loc`: `Autosave`) + `" - "` + text [C parts, I order]. `SaveGame` (`0x4e5fe0`) strips `\ / : * ? " < > |`, appends `.sav` and writes `Profiles\<user>\Save\<name>.sav`; an existing file of that name is deleted first [C]. The kit's saves are therefore `Autosave - TRF E0 <system>.sav`, and a second `AutoSave` with the same text overwrites the first [C]. `"%x %X"` (`0x725488`) is only the date format of the load menu, not part of the file name [C].
- The native calls `SaveManager::SaveGame(name, 0)` directly; there is no deferred flag [C]. It shows `#UI_AutoSaveStarted` ("Saving...") before and `#UI_SaveError` on failure [C]. `SaveGame` refuses game states other than 5, 6 and 0x13 [C, save-format.md], so a call during location loading probably fails [I].
- The game's calls (about 250 in 112 quest files, plus `include/AutoTest*.script`) all run from script events after the location is up: `Timer_Seq` callbacks (`mission_1` `autosaveMission`, 1 s after the mission end; `AutoTest2` 2 s after entry), trigger actions (`mission_4_52` `GoOut_Elio`, an `inside` trigger), dialog callbacks (`mission_9c` `Hero_Answer`), and directly before `Long_Jump`/`TeleportToLocation` (`mission_7g_01`, `AutoTest2`) [C]. None calls it from `activate.script` or at load time [C]. A trigger action is therefore a safe place [I].

### The save kit (`exp_saves.script`)

On `OnActivate` of a system that `TRF.exp.saves` (keyed by the lowercase `GetCurrentLocation()`) has not recorded as saved, the kit arms a 20 s `timer` trigger with the string action `TRF_Saves_Fire(<gen>)--`. When it fires in the same entry, the kit marks the system as saved (before the call, so the save contains the mark), logs `saves: autosave <system> TRF E0 <system>` and calls `AutoSave("TRF E0 <system>")`. It skips (and logs `saves: skip <system> (<reason>)`):

- the first system this `TRF` has seen (`cnt.enter < 2`): a new game's first system holds the scripted intro, and E0.2 wants a save after a jump;
- mission 1: the quest label `CurrentQuest` stays unset until mission 2's `ACTION_INIT` sets it to `"2"` (`AUTOSAVE=2` turns this guard off; mission 1 is scripted, so prefer the manual recipe there);
- systems already saved, and everything after 6 saves. The record lives in `TRF`, so the cap holds for the playthrough, not only the session.

A timer that fires during a jump, after another entry or after a load (`gen` differs) logs `saves: stale timer` and does nothing. If the autosave option is off, the log still shows `saves: autosave` but no file appears.

### Which saves the experiments need

- E0.1: none.
- E0.2: one save in any quiet system after at least one jump (the kit's first `Autosave - TRF E0 <system>` is that save), then quit, relaunch and load it. Also one save made with `TRAFFIC_ENABLED=0` for the "TRF nil" case: with the DLL module disabled no `TRF` exists and the kit does not run, so save manually. `tools/make-test-saves.sh` can instead derive the `trf-nil`, `trf-v1`, `trf-big` and `trf-bad` variants from the one baseline, so a single real save is enough.
- E0.3: none.

### Manual recipe (fallback)

1. `EXP=2 mods/traffic/install-test.sh`, then `run-test.sh`, and in the clone start a new game.
2. Leave the first system (after the intro), wait in the next system until nothing is happening, and save from the in-game menu under a name such as `Base` (no `\ / : * ? " < > |`).
3. Quit. The game writes `~/Games/Heroic/sw3-tp-test/Profiles/secustor/Save/<name>.sav` (autosaves: `Autosave - <text>.sav`).
4. Copy the baseline into the repo-ignored directory for the tools and build the variants:

        mkdir -p .work/saves
        cp ~/Games/Heroic/sw3-tp-test/Profiles/secustor/Save/Base.sav .work/saves/Base.sav
        # a kit save instead: cp ".../Save/Autosave - TRF E0 <system>.sav" .work/saves/Base.sav
        BASE=.work/saves/Base.sav sh mods/traffic/tools/make-test-saves.sh
